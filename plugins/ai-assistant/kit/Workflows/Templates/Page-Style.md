# Page Style

How to build any page the user reads: the inbox review and meeting prep. Workflows point here so the style lives in one place.

The daily brief has its own look and its own template: `Workflows/Templates/Daily-Brief.html` (a soft purple background with white cards). Fill that file instead of using the colors below. The rules on dates, times, the status line, and relative links still apply.

## HTML pages

- A complete, standalone HTML document that opens in any browser with no internet connection. No outside scripts, fonts, or images.
- Light mode only. System fonts. Body text at least 16px. Readable line length (about 70 characters). Comfortable on a phone.
- Colors: warm paper background `#fbf6ec`, panels `#fffdf8`, ink text `#1f1713`, muted text `#5e5047`, borders `#e5d7c3`, blue accents and links `#3b6e8f`.
- Real headings and lists. No decorative gradients, dark mode, or tiny text.
- Times as AM/PM. Dates written out, such as "Tuesday, November 3".
- A small status line at the bottom when email or calendar could not be read, for example: "Calendar read. Email not connected this run."
- Links to other files in this folder use relative paths, for example `../People/Maria Lopez.md` from a page in `Meetings/`.

## Plain-text drafts

Used only for an email draft the mailbox can't hold: plain sentences, no formatting, the recipient and subject on the first two lines, and the last line `Not sent. Review it, then send it yourself.`

## Chat reply after saving a page

One or two lines: what was saved, the file name, anything that could not be read, and "Nothing was sent" when drafts were made.
